# Slow Mail - Assumptions

Status: pre-alpha. Last updated: 2026-10-20.

Every assumption the design rests on, with its current status:

- **VERIFIED** - the primary text was read (Microsoft docs source, vendor artifact, upstream repo). This is a statement about *documentation*. Nothing in this repository has been run against a real Microsoft 365 tenant or a real Paper Pro, so no live behaviour is VERIFIED.
- **UNVERIFIED** - from memory, inference, a search snippet, or a community report. Not confirmed.
- **FALSIFIED** - evidence found that the assumption is wrong.

The fake Graph server (`tools/fake_graph/server.py`) encodes our *model* of Graph. Tests passing against it prove that the client matches the model, not that the model matches Microsoft.

Evidence pointers: `GC` = [GRAPH_CONTRACT.md](GRAPH_CONTRACT.md) section, `COMPAT` = [COMPATIBILITY.md](COMPATIBILITY.md) section or row, `RL` = [RESEARCH_LOG.md](RESEARCH_LOG.md) entry.

## A. Microsoft Graph and Entra

| # | Assumption | Status | Evidence | What breaks if false |
|---|---|---|---|---|
| ASM-01 | The `archive` well-known folder exists in the target mailbox (`GET /me/mailFolders/archive` returns 200). | UNVERIFIED | GC 0 (headline a), GC 4 note 2, GC 12.1. The name is documented (VERIFIED) but existence for a mailbox that never used Archive is not. | `Do / Archive` cannot work. Per D4 the app must show "Archive folder not available" and must not fall back to Deleted Items. The adapter sends the literal name `archive` and distinguishes a missing destination only if Graph answers with the code the adapter expects (`ErrorFolderNotFound`, itself UNVERIFIED, see ASM-15); if Graph instead answers `ErrorItemNotFound`, D21 would misread it as "message already gone" (TEST_PLAN A03). |
| ASM-02 | `Prefer: IdType="ImmutableId"` is honoured on `move`, so the message id stays the same after a move within the mailbox. | UNVERIFIED | GC 3.2 (VERIFIED doc text: id stable across folder moves in one mailbox), GC 3.3 (consequences UNVERIFIED), GC 4.2 (move page says it "creates a new copy", which conflicts with id stability), GC 12.5. | Local rows keyed by the old id; a later PATCH or retry returns 404 and D21 would call a message "gone" when it merely changed id. The adapter must take `new_id` from the move response (`MoveResult::new_id`). |
| ASM-03 | The header is sent on every request (delta, get, move, patch, attachments) so ids are always in the same format. | UNVERIFIED | GC 3.1: header "only applies to the request it is included with" (VERIFIED). Mixed formats are inference. | Same message appears under two ids; duplicates in the queue, or false removals. Meta-test: GC 11.9 item 1. |
| ASM-04 | Delta reports a message that was moved out of the Inbox as an `@removed` entry. | VERIFIED (docs only) | GC 2.5, GC 2.6: `@removed` with `reason: "deleted"` is used for "deleted or moved from the folder". | A message archived in another Outlook client would stay in the Slow Mail queue (A08). |
| ASM-05 | Delta also reports a message that was moved out and later back in (immutable ids). | **UNVERIFIED, doc says the opposite** | GC 2.6, GC 3.3: known issue dated 2026-02-25, "you might miss some change notifications". Treated as a real gap. | A message the user returned to the Inbox elsewhere stays hidden. See RISKS R-DELTA-MOVEBACK. Mitigation (periodic reconcile) is a design requirement, not proven. |
| ASM-06 | The tenant allows the device-code flow for this app (Conditional Access does not block it) and does not require admin consent for `Mail.ReadWrite`. | UNVERIFIED | GC 1.7 (consent is tenant policy, UNVERIFIED), GC 1.8 (Microsoft recommends blocking device code; protocol tracking; `AADSTS530036`), GC 12.10. | No sign-in at all, or sign-in that stops working at the next refresh. Tenant-admin conversation (D18); A15. |
| ASM-07 | The public-client setting "Allow public client flows" can be enabled on the owner's app registration. | UNVERIFIED | GC 1.7 (requirement VERIFIED; whether the owner's tenant permits it is not). | Token call fails with `AADSTS7000218`. |
| ASM-08 | Entra does not rely on `slow_down` for device-code polling, but may send it; handling it is harmless. | UNVERIFIED | GC 1.4: `slow_down` is absent from Microsoft's error table (VERIFIED absence). | If Entra rate-limits polling with an undocumented error, the client could poll too fast; it must still never poll faster than `interval`. |
| ASM-09 | `offline_access User.Read Mail.ReadWrite` is the complete scope set for the MVP; adding `Mail.Send` later needs a new interactive sign-in. | VERIFIED (docs) | GC 1.7: refresh scope must be a subset of already-consented scopes. The exact error on an attempt is UNVERIFIED. | Sending later requires a fresh device-code sign-in. |
| ASM-10 | `/me/mailFolders/inbox/messages/delta` accepts the literal well-known name `inbox` in the path. The Graph adapter header uses this form. | UNVERIFIED | GC 2.1 and GC 12.2: docs always show a folder id; GC recommends resolving the id once. | Initial sync fails with 4xx and the resync rule would loop on it. Fix is to resolve the inbox id first. (Confirmed by reading `src/graph/src/graph_backend.cpp`: it builds `{base}/me/mailFolders/inbox/messages/delta`.) |
| ASM-11 | `flag` can be selected in delta, and a flag change made in another Outlook client produces a delta entry. | UNVERIFIED | GC 5 note 7, GC 12.4. | D20 (unflag elsewhere restores to queue) and D6 (pre-existing flagged messages visible with correct state) do not work; deferred messages only return through an explicit un-defer. |
| ASM-12 | `$select=id,name,contentType,size,isInline` is honoured on the attachments collection, so `contentBytes` is not returned. | UNVERIFIED | GC 6.2 (default listing includes `contentBytes`, VERIFIED; `$select` on the collection is generic-doc support only), GC 12.8. | Attachment bytes would be downloaded, breaking the "no attachment bytes" control. Mitigation: response size cap in the transport and a contract-test violation record (GC 11.7). |
| ASM-13 | `Prefer: outlook.body-content-type="text"` returns a text body; `body.contentType` says which format came back. | VERIFIED (docs) | GC 6.1. Conversion edge cases UNVERIFIED. | HTML arrives; the sanitiser (`html_to_text`) is the safety net. |
| ASM-14 | Several `Prefer` values can be sent in one header line, comma-joined. | UNVERIFIED | GC 2.1, GC 12.6. | `odata.maxpagesize` or `IdType` silently ignored. Fix is separate header lines. |
| ASM-15 | A deleted or moved message returns 404 with code `ErrorItemNotFound`, and a missing destination folder returns a different 404 code (the adapter, fake server and unit tests assume `ErrorFolderNotFound`, which is our invention until checked). | UNVERIFIED (SNIPPET) | GC 8.5, GC 11.6. | D21 misclassifies: gone messages are marked Failed instead of Abandoned, or other 404s are mistaken for "already gone". |
| ASM-16 | An expired or evicted messages delta link yields a 4xx the client treats as "resync" (400, 404 or 410). | UNVERIFIED (statuses and codes) / VERIFIED (that tokens can be evicted) | GC 2.7, GC 12.3. | Initial-sync loop or a stuck sync. The client resyncs on any 4xx other than 401/403/429 (GC 2 note 6). |
| ASM-17 | A retried move after an unknown outcome is safe: if the first attempt succeeded the retry returns 404 (or a harmless 201). | UNVERIFIED | GC 4 note 5, GC 8 note 12. | Duplicate or misreported actions (A06). |
| ASM-18 | The Graph and Entra hosts are reachable over TLS 1.2/1.3 with certificate verification from the device and from this host. | UNVERIFIED | COMPAT 5 (TLS row): the system policy on Move/rM2 restricts cipher suites. Our app uses its own libcurl + OpenSSL from the SDK sysroot, so this is an item to verify, not a known blocker. | Network error on every call; no insecure fallback exists (verification cannot be disabled). |

## B. Device, SDK and launcher

| # | Assumption | Status | Evidence | What breaks if false |
|---|---|---|---|---|
| ASM-19 | The Paper Pro SDK Qt version is compatible with the Qt 6.4 host build: code that compiles on host Qt 6.4.x also compiles against SDK Qt 6.8.2, and behaves the same on the device. | UNVERIFIED | COMPAT 1 toolchain facts: SDK Qt **6.8.2**, device xochitl Qt **6.10.3** on OS 3.28; official CMake sample uses `qt_standard_project_setup(REQUIRES 6.5)` (SNIPPET). The Qt-free core is unaffected (D17). The host build deliberately uses only what Qt 6.4 offers. |
| ASM-20 | The SDK sysroot supplies libcurl, OpenSSL 3, SQLite and Qt Quick (no Widgets, no Qt Sql); nlohmann/json can be vendored or found. | UNVERIFIED for nlohmann/json and for the *device*; VERIFIED for the SDK listing | COMPAT 1; RL L3 (sysroot listing shows libssl.so.3, libcurl, libsqlite3; a listing shows what the SDK ships, not what the device ships). | The device build fails to link or run. nlohmann/json is header-only and can be vendored. |
| ASM-21 | The Paper Pro SDK env script is `environment-setup-cortexa53-crypto-remarkable-linux` and exports `CMAKE_TOOLCHAIN_FILE`. | VERIFIED [vendor] (SDK 5.7.119) | COMPAT 0 and 1, RL L2, L3. | ASM-22 | Takeover (stop `xochitl`, run the app with `QT_QUICK_BACKEND=epaper -platform epaper`, restart `xochitl`) works on the Paper Pro and leaves the stock UI recoverable. | UNVERIFIED | COMPAT 1 run-time flags (official route is SNIPPET; verified only on rM2), COMPAT 3 breakages 9-10 (`remarkable-fail.service` reboot, passcode re-prompt). | Stage 1 gate fails (D24); move to AppLoad route B. |
| ASM-23 | AppLoad / remagic can launch our binary on the current OS (3.28.0.172; 3.29.0.153 seen in the wild on 2026-10-18). | UNVERIFIED | COMPAT 1 matrix and 3 breakage 1: AppLoad >= 0.6.0 plus a hashtab rebuild reported to work on 3.28 (single reports). | ASM-24 | The remagic one-line installer produces a working launcher on OS 3.28. | **FALSIFIED** | COMPAT 0 and 3 breakages 1-3: `main` pins AppLoad v0.5.3, which crash-loops `xochitl` on 3.28; fix PR #3 open, not merged when checked. | Using the one-liner on 3.28 puts the device in a crash-loop until reboot to stock. Do not use it; follow COMPAT 3 workaround, and only after the owner's go/no-go (D14). |
| ASM-25 | An external Qt Quick app can run through AppLoad's `qtfb` route on the Paper Pro. | **FALSIFIED** | COMPAT 2 option B (VERIFIED [3P]): no `/dev/fb0`, no linuxfb plugin. | Route B has to be a native QML module, not our standalone binary. |
| ASM-26 | Qt Quick output on E Ink is legible and responsive enough with static, no-animation screens (full refresh at page turns). | UNVERIFIED | COMPAT 6 (guidance from other apps, VERIFIED [3P]); `libqsgepaper` partial-refresh API undocumented. | Stage 1 gate fails (legibility, latency). |
| ASM-27 | Wi-Fi is available during a session (the user is on a known network when they refresh). | UNVERIFIED | COMPAT 5: Move goes into deep suspend ~40 s after the last touch, with Wi-Fi and USB down and no network or timers running (Move evidence; Paper Pro UNVERIFIED). Reconnect latency after resume: no evidence found. | Refresh fails with Network errors. Design copes: cached mail stays readable, actions queue (D8). A refresh must be user-initiated with the device awake; device test item in tests/device/CHECKLIST.md. |
| ASM-28 | There is no secure keystore on the device; tokens are stored in plaintext inside a 0600 SQLite file on a volume protected only by device encryption. | UNVERIFIED (absence of evidence) | COMPAT 5 (secure storage row): no keyring, Secret Service, TPM API or libsecret found; existing apps keep secrets in plaintext. | ASM-29 | The device clock can be wrong after a long sleep or when Wi-Fi was off, and is UTC. | UNVERIFIED | COMPAT 5 (clock row: Move uses UTC; NTP behaviour no evidence; Paper Pro UNVERIFIED), COMPAT 8.8. | Wrong "Downloaded at" display; token `expires_at` miscomputed (a 401 then forces a silent refresh); TLS certificate dates could fail on a badly wrong clock (inference). | ASM-30 | The app's data directory `/home/root/.local/share/slowmail` is writable, persistent across OS updates and sits on the encrypted `/home` volume. | UNVERIFIED for this path | COMPAT 3 breakage 7 and COMPAT 5: `/home/root` survives OS updates; `/home` on `/dev/mapper/home-encrypted-disk` (VERIFIED [3P], Move/Paper Pro). | Data loss on update or app start failure. |
| ASM-31 | `systemd` stop/start of `xochitl` from a shell script launched over SSH is permitted and the script survives long enough to restart it. | UNVERIFIED | COMPAT 3 breakages 9-10; Paper Pro not tested. | Device left without a UI until reboot. The wrapper restarts `xochitl` from a trap, but a SIGKILL still leaves it stopped (COMPAT rmweb note). |
